# Commit Semantic

Semantic analysis of commits using Team Agent architecture:
split by module, classify functional/non-functional, score, aggregate, distill.

## Prerequisites

Requires `data/commit-extract/*.yaml` files produced by `/commit-extract run`.
Each commit in those files must have a `commit_log` field (LLM-regenerated by commit-extract workers).

## Pipeline Stages

### 1. split

Load commits from `data/commit-extract/`, split by module into **change units**.

- Reads `commit_log` field (canonical) with `original_message` as fallback
- Module detection via keyword matching on `MODULE_KEYWORDS`
- Unmatched commits get `unknown` module
- Output: `data/commit-semantic/units/all.yaml`

### 2. analyze

Classify each unit as **functional** or **non-functional**, then score functional units.

- Classification by prefix: `feat`/`bugfix`/`optimize` = functional; `refactor`/`test`/`config`/`cleanup` = non-functional
- Scoring (functional only): 0-10 on clarity, domain fit, reusability
- Tiers: high (>=8), medium (5-7), low (<5)
- Output: `data/commit-semantic/functional/{high,medium,low}/units.yaml`, `data/commit-semantic/non-functional/all/units.yaml`

### 3. aggregate

Group high-scored functional units by module into **patterns**.

- Reads `functional/high/units.yaml`
- Groups by `module` field
- Output: `data/commit-semantic/patterns/{module}.yaml`

### 4. distill

Extract **canonical demands** from module patterns.

- Reads `patterns/*.yaml`
- Synthesizes top 5 demands per module using LLM analysis
- Output: `data/commit-semantic/canonical-demands.yaml`

### 5. export

Generate structured **summary statistics** from canonical demands and patterns.

- Reads `canonical-demands.yaml`
- Classifies demands by development type (feature/bugfix/refactor/other)
- Computes bugfix ratio, pattern count, high-frequency patterns
- Output: `data/commit-semantic/summary.yaml` (ExportSummary format)

## Worker Agents

LLM analysis stages (classify, score, distill) are delegated to **worker agents**
spawned via the Task tool. Workers receive batched units and return structured results.

### Worker Prompt Templates

- `prompts/classify.md` — classify unit as functional/non-functional
- `prompts/score.md` — score functional unit on quality dimensions
- `prompts/distill.md` — synthesize canonical demands from patterns

### Spawning Architecture

- `_batch_units(units, batch_size=10)` — splits units into batches
- `_spawn_worker(batch, prompt_template)` — delegates to Task agent
- `_get_worker_prompt_template(name)` — loads prompt from `prompts/{name}.md`
- Set `COMMIT_SEMANTIC_USE_TASK_AGENTS=1` to enable real Task agents

## Output Schema

```
data/commit-semantic/
  units/all.yaml              # All change units
  functional/
    high/units.yaml           # Score >= 8
    medium/units.yaml         # Score 5-7
    low/units.yaml            # Score < 5
  non-functional/all/units.yaml
  patterns/{module}.yaml      # High-tier grouped by module
  canonical-demands.yaml      # Synthesized demands
  state.json                  # Analysis statistics
```

## Usage

```bash
/commit-semantic run              # Full pipeline
/commit-semantic step              # Run next stage only
/commit-semantic resume            # Continue from breakpoint
/commit-semantic reset             # Clear state, keep artifacts
```
