## 前置：架构上下文

**整个 sematic-harness repo 是一个 Claude Code skill 插件**，由宿主 repo 安装后在 Claude Code (CC) 环境中执行。

### 执行模型

- **Claude Code** 读取 SKILL.md 的 prompt 指令
- **Claude Code 自身（LLM）** 做推断、合成、决策
- **`src/semantic/` Python 脚本** 作为 CLI 工具被 Claude Code 调用，负责：
  - 结构化 I/O
  - 数据校验
  - 持久化
- **Python 代码不需要包含"智能逻辑"** — 智能来自 Claude Code 执行 prompt

## 🔴 新识别的高优先级问题

### 问题 A：`build_candidates.py` 不应该有硬编码兜底，应该报错

**位置**: `src/semantic/build_candidates.py:28-66`

**问题**：
当前代码在非 CC 环境下会默默返回硬编码的占位符数据：

```python
def synthesize_domain_candidates(domain_signals: List[Dict[str, Any]]) -> List[Dict[str, Any]]:
    for signal in module_grouping_signals:
        candidate = {
            'id': generate_stable_id('repository_structure', 'domain'),
            'name': 'Repository Structure',   # ← 硬编码兜底
            'summary': 'Core repository organization...',  # ← 硬编码兜底
            ...
        }
```

**用户反馈**：
> "不要兜底，如果不是 CC 类的执行环境，就应该报错"

**正确行为**：
- 在 CC 环境：CC 通过 prompt 生成真实数据，Python 接收并处理
- 在非 CC 环境：Python 应该**检测到缺少必需数据并报错**，而不是返回占位符

**建议修复**：

```python
def synthesize_domain_candidates(domain_signals: List[Dict[str, Any]]) -> List[Dict[str, Any]]:
    """
    Synthesize domain candidates from domain signals.

    In CC environment: Receives real candidate data from LLM-generated YAML
    In non-CC environment: Should fail with clear error
    """
    candidates = []

    for signal in domain_signals:
        # Validate that signal contains required fields from CC
        required_fields = ['name', 'summary', 'boundary']
        missing = [f for f in required_fields if f not in signal]

        if missing:
            raise ValueError(
                f"Signal missing required fields: {missing}. "
                f"This function expects data generated by Claude Code prompts. "
                f"Cannot synthesize candidates without LLM-generated content."
            )

        # Use real data from CC, not hardcoded fallbacks
        candidate = {
            'id': generate_stable_id(signal['name'], 'domain'),
            'name': signal['name'],  # ← From CC
            'summary': signal['summary'],  # ← From CC
            'boundary': signal['boundary'],  # ← From CC
            ...
        }
        candidates.append(candidate)

    return candidates
```

**影响**：
- ✅ 明确失败优于默默返回无意义数据
- ✅ 清晰的错误消息指导用户
- ✅ 防止在非 CC 环境下产生垃圾数据

### 问题 B：`apply_review.py` 透传前应该验证数据完整性

**位置**: `src/semantic/apply_review.py:27-40`

**问题**：
当前代码直接透传，没有验证 CC 是否真的提供了决策：

```python
def convert_to_review_decision(recommendation: Dict[str, Any], rec_type: str) -> Dict[str, Any]:
    rec_action = recommendation.get('recommendation', {}).get('action', 'backlog')  # ← 默认值
    final_action = rec_action  # ← 直接透传
```

**用户反馈**：
> "不要兜底，如果不是 CC 类的执行环境，就应该报错"

**正确行为**：
- 在 CC 环境：CC 已经做了决策，Python 验证并透传
- 在非 CC 环境：如果缺少必需的决策数据，应该报错

**建议修复**：

```python
def convert_to_review_decision(recommendation: Dict[str, Any], rec_type: str) -> Dict[str, Any]:
    """
    Convert a recommendation into a review decision.

    In CC environment: CC has already made the decision via prompts
    In non-CC environment: Should fail if decision data is missing
    """
    # Validate that CC provided the decision
    if 'recommendation' not in recommendation:
        raise ValueError(
            f"Recommendation missing 'recommendation' field. "
            f"This function expects decisions made by Claude Code prompts. "
            f"Cannot generate review decisions without LLM input."
        )

    rec_data = recommendation['recommendation']

    # Require explicit action from CC, no defaults
    if 'action' not in rec_data:
        raise ValueError(
            f"Recommendation missing 'action' field in recommendation data. "
            f"Claude Code must provide explicit action (keep/drop/merge/verify_first/backlog)."
        )

    rec_action = rec_data['action']

    # Transparent pass-through of CC's decision
    final_action = rec_action

    # ... rest of the function
```

**影响**：
- ✅ 确保只处理 CC 生成的真实决策
- ✅ 防止在非 CC 环境下产生无效决策
- ✅ 清晰的错误消息

### 正确的理解 ✅

**Semantic 层的设计是正确的**：
- Python 代码是"哑管道"（dumb pipeline）

### 实现问题 ⚠

**当前实现的问题**：
- ❌ 有硬编码兜底（占位符数据）

**"Fail Fast, Fail Loud"**：
- 在 CC 环境：正常工作

- 不要默默返回占位符数据
